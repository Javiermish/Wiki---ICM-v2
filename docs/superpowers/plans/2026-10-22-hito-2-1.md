# Hito 2.1 — Implementation Plan

**Goal:** Autenticación Supabase SSR y perfiles/roles seguros sin alterar el catálogo demo.
**Architecture:** Clientes por entorno; identidad con getClaims y privilegios consultados a PostgreSQL. Perfiles y roles separados, RLS y RPC administrativa auditada sin claves privilegiadas.
**Tech Stack:** Next.js 16, React, TypeScript, Supabase Auth/PostgreSQL, pnpm.
**Spec:** Solicitud Hito 2.1 y documentación de producto del repositorio.

## Restricciones
- Sin commit, push, ramas, worktrees, despliegue ni migraciones remotas.
- Solo autenticación/perfiles/roles reales; catálogo, aportes y favoritos conservan su naturaleza demo/local.
- Cloudflare R2 futuro; no Supabase Storage.
- Registro exclusivamente student; correo confirmado obligatorio.

## Revisión prioritaria
- Cookies manipuladas: verificar identidad y consultar rol actual.
- URLs externas o codificadas: destinos internos permitidos solamente.
- Actualización de perfil manipulada: privilegios por columna y RLS propia.
- Cambios de rol concurrentes: RPC transaccional, auditoría, sin revocar administradores desde la app.
- Respuestas privadas y renovación: no-store y propagación de cookies/cache headers.

## Tareas
- [x] Backend SQL: migración perfiles/roles/eventos, RPC, pruebas SQL transaccionales y procedimiento bootstrap verificado.
- [x] Sesión: dependencias, clientes SSR/browser, proxy, validación y autorización; pruebas unitarias de límites.
- [x] Flujos: acciones de registro/login/logout/recuperación/contraseña/perfil y confirmación token_hash; pruebas con dobles claramente identificados.
- [x] Interfaz: páginas de auth/cuenta/admin, cabecera responsive, moderación protegida conservando demo.
- [x] Validación local: 163 tests con HTTP, PostgreSQL local, revisión de seguridad, lint/build y 182 checks de navegador claro/oscuro móvil/escritorio. Sesiones reales y vistas autenticadas pendientes externas.
- [x] Entrega: configuración externa, correo/URLs, migraciones, primer admin y resultados reales/pendientes en docs/HITO_2_1.md.

Cada unidad agrega primero sus pruebas pertinentes, ejecuta y registra los resultados. No se requiere aprobación intermedia: ejecución autónoma expresamente autorizada por el usuario.

Integración remota, correos reales y sesiones con tres roles pendientes de configuración/validación externa, no acreditadas por dobles SDK ni PostgreSQL con esquema Auth mínimo.
